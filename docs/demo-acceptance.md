# 演示与故障验收清单

## 两套演示入口

在线演示用于展示真实上传和分析。开始前确认 `/api/health` 的 `vision` 为 `configured`，再上传来源合规的公开样图；若模型失败，应展示失败原因和重试入口，不能切换文字把失败伪装为成功。

离线演示用于网络或模型不可用时回放既有报告。先在目标数据库执行：

```powershell
.\.venv\Scripts\python.exe scripts\seed_demo.py
```

断开网络后启动应用，打开 `/records`，依次查看通道堵塞、暗光不确定、插线板覆盖和多隐患四份记录。历史列表带“离线回放”徽标，报告顶部说明它使用合成示意图且没有调用模型；图片自身也写有 `OFFLINE HISTORICAL REPLAY`。四份记录分别覆盖单隐患、无明确隐患、无法确认项和多隐患，并保留真实法规快照。重复执行种子命令不会增加记录。回放不可编辑或补录，也不进入业务仪表盘统计。

## 五分钟软件演示顺序

1. 请求 `/api/health`，说明数据库、视觉提供方、文本模式、内部复核和访问保护状态。
2. 在线条件正常时上传一张合规图片，展示真实后台步骤、照片证据、法规原文、内部等级和整改建议。
3. 完成人工确认或修正，刷新页面证明结果和审计记录仍存在。
4. 打开历史记录和打印视图，说明引用使用当次快照。
5. 切换到一份离线回放，明确说明这是断网保底，不是刚刚完成的实时推理。
6. 展示 `docs/evaluation.md` 的实际样本数和模型标识；若仍为示例报告，只讲评测方法，不讲准确率结论。

## 故障分支

| 场景 | 期望结果 | 自动化证据 | 现场仍需执行 |
| --- | --- | --- | --- |
| 模型超时/网络失败 | 任务进入 `failed`，保存稳定错误，可在恢复后重试 | `tests/test_vision_flow.py` | 对真实服务断网或使用测试接入点演练一次 |
| 无匹配条款 | 不虚构引用，等级与建议转人工核验 | `tests/test_workflow_agents.py`、`tests/test_knowledge.py` | 用不在知识库范围内的合规样图核对报告措辞 |
| 模糊或遮挡 | 保存 `poor/fair` 质量和无法确认项，不创建假隐患 | `tests/test_vision_flow.py`、离线暗光回放 | 真实模糊照片一次 |
| 无明显隐患 | 隐患数组为空，统计不增加 | `tests/test_vision_flow.py`、离线暗光回放 | 真实无隐患照片一次 |
| 多隐患 | 每项独立保存证据、等级、建议和法规快照 | `tests/test_demo_seed.py`、离线多隐患回放 | 真实多隐患照片一次 |
| 服务重启 | 执行中的任务转明确失败；已完成报告和图片保留 | `tests/test_vision_flow.py`、`tests/test_deployment.py` | 公网容器执行一次重启 |
| 模型完全不可用 | 离线回放无需外部 API/CDN，且全程明确标识 | `tests/test_demo_seed.py`、`tests/test_frontend_safety.py` | 目标机器断网查看四份报告 |

## 评测冻结条件

正式对外描述模型效果前，至少完成 10 张冒烟样本和一组未参与调参的验证样本。目标仍为约 50 张；不足时报告必须写实际数量。评测记录必须包含模型/权重标识、样本分组、误报、漏报、精确率、召回率、请求失败率和端到端 P50/P95。阈值或类别映射变更后要生成新预测文件，不能覆盖旧结果后继续沿用旧结论。

仓库当前只提交格式示例，没有真实现场标注和模型预测，因此还不满足模型效果冻结条件。功能演示可以使用规则链路和离线回放，但讲解必须区分实时分析、规则处理、人工复核和历史回放。
