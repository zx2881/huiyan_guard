# 开发基线与接口设计

日期：2026-09-16
范围：实施方案第 1 步中的仓库内工程工作

## 目标

在不扩大产品范围、不改变现有业务流程的前提下，固定项目配置、运行方式和 API 契约，使另一名开发者能够按 README 启动应用，并通过自动化测试验证基础行为。

本阶段完成以下事项：

- 集中管理数据库、上传目录和火山方舟配置；
- 让 `.env.example` 中的 `DATABASE_URL` 和 `UPLOAD_DIR` 真正生效；
- 新增不泄露敏感信息的健康检查接口；
- 为现有接口、数据字段、状态和错误语义建立文档；
- 建立不调用真实模型、不污染运行数据的基础测试；
- 同步 README 中的配置和测试说明。

真实模型账号、接入点、配额验收，文本模型选型，赛事报名和材料起草依赖团队外部信息，不在本次代码变更内完成。视觉输出强化、图片内容校验和异步工作流属于后续实施步骤。

## 方案选择

采用增量基线方案：保留当前 FastAPI、原生前端、`sqlite3` 和同步巡检流程，只提取配置、补健康检查、记录契约并添加基础测试。

未采用完整分层重构，因为拆分路由、服务和数据访问层会扩大第 1 步范围并增加回归风险。未采用仅增加配置与健康接口的最小方案，因为它无法提供可重复验收证据，也不能消除接口字段和状态歧义。

## 架构与组件

### 集中配置

新增 `backend/app/config.py`，使用 `pydantic-settings` 定义不可变配置对象。配置项包括：

- `DATABASE_URL`：仅支持当前使用的 SQLite URL；默认 `sqlite:///./data/app.db`；
- `UPLOAD_DIR`：默认 `./data/uploads/inspections`；
- `ARK_API_KEY`：默认空；
- `ARK_BASE_URL`：默认方舟兼容 API 地址；
- `ARK_MODEL`：默认空。

相对文件路径统一相对于仓库根目录解析，不依赖启动命令的工作目录。配置通过带缓存的 `get_settings()` 获取；测试可清除缓存并通过环境变量注入临时路径。

SQLite URL 若不是 `sqlite:///` 本地文件格式，应用应在启动阶段给出明确配置错误。本阶段不引入其他数据库驱动。

### 数据库

`backend/app/database.py` 从集中配置解析数据库路径，按需创建父目录并返回设置了 `sqlite3.Row` 的连接。连接由上下文管理器负责提交、回滚和关闭，避免当前 `with sqlite3.Connection` 只管理事务但不显式关闭连接的问题。

保留现有三张表和字段，不执行破坏性迁移。测试使用独立临时数据库。

### 上传目录

`backend/app/main.py` 从集中配置取得上传目录并创建目录，`/uploads` 继续映射到同一路径。现有文件名生成和接口返回保持兼容。

由于 FastAPI 静态目录在应用构造时绑定，应用应提供 `create_app()` 工厂；模块级 `app` 仍保留，确保现有 Uvicorn 命令不变。测试通过环境变量和工厂创建隔离实例。

### 视觉客户端

`VisionClient` 接受可选配置对象，默认调用 `get_settings()`。它不再自行加载 `.env` 或直接读取 `os.environ`。`enabled` 仍仅在 API Key 与模型标识同时存在时为真，现有演示模式行为保持不变。

### 健康检查

新增 `GET /api/health`，成功时返回：

```json
{
  "status": "ok",
  "database": "ok",
  "vision": "configured"
}
```

未配置模型时 `vision` 返回 `unconfigured`，但整体服务仍为 `ok`，因为演示模式是当前允许的运行方式。接口只执行轻量数据库查询，不调用外部模型。

数据库不可用时返回 HTTP 503，响应只包含稳定的公开错误信息，不包含绝对路径、SQL、堆栈、密钥或原始异常。

## API 契约文档

新增 `docs/api.md`，分别记录：

- 页面路由和当前四个 API；
- 请求格式、响应字段、HTTP 状态和错误语义；
- `inspections`、`hazards` 和 `regulations` 的当前字段；
- 当前状态值 `analyzing`、`completed`、`failed` 的含义；
- 演示模式与真实视觉模式的区别；
- 实施方案中的计划接口和计划状态，且明确标为“尚未实现”。

文档描述必须以代码和测试结果为准。后续修改 API 时先更新契约，再同步前后端和测试。

## 数据流

应用启动时加载一次配置，解析并创建数据库、上传目录，初始化数据表，然后挂载静态资源。上传巡检仍沿用当前同步流程：校验表单、保存图片、建立巡检记录、进入演示或真实视觉分支、保存结果并返回。

本阶段不改变 `POST /api/inspections` 的等待行为，不新增后台任务，也不修改数据库状态模型，以避免提前侵入第 4 步工作流设计。

## 错误处理与安全

- 无效 SQLite URL 在启动时失败并给出不含密钥的明确错误；
- 健康检查捕获数据库异常并返回固定 503 响应；
- 配置对象和健康响应不得序列化或展示 API Key；
- `.env` 继续由 `.gitignore` 排除，`.env.example` 只包含空密钥；
- 测试和文档不得记录真实供应商凭据；
- 现有上传安全缺口不在本阶段伪装为已修复，继续在进展文档中保留。

## 测试设计

使用 `pytest` 和 FastAPI `TestClient`。如当前锁定依赖不能直接提供测试运行所需包，则在 `requirements-dev.txt` 中单独记录测试依赖，不把开发工具混入生产依赖。

测试必须通过临时环境变量把数据库和上传目录指向 pytest 临时目录，并在创建应用前清除配置缓存。不得写入仓库的 `data/`，不得访问真实方舟 API。

最低覆盖：

1. 默认值与环境变量覆盖能解析到预期路径；
2. 非 SQLite URL 被拒绝；
3. `/api/health` 在数据库可用且模型未配置时返回 `ok`/`unconfigured`；
4. 配置了假的 Key 和模型标识时只报告 `configured`，不发起外部请求；
5. 三个页面及公共样式可访问；
6. 空历史、未知编号、非法场景和非法 MIME 返回当前约定结果；
7. 未配置模型的演示上传可保存并查询，数据库与图片均位于临时目录；
8. 健康响应和错误响应不包含密钥或本地绝对路径。

真实视觉调用不属于自动化测试。团队配置凭据后，按 README 手工上传一张可公开图片，记录模型标识、成功/失败结果和时间，但不记录密钥。

## 文档与兼容性

README 保留现有启动命令，补充各配置项实际含义、相对路径基准、健康检查和测试命令。`docs/02_当前进展.md` 仅在测试实际通过后更新相应缺口，不能提前宣称已验收真实模型或全新环境安装。

现有页面 URL、API URL、SQLite 表名和模块级 `backend.app.main:app` 均保持兼容。配置改造不移动已有运行数据；默认路径仍指向仓库内原位置。

## 验收标准

- 独立临时配置下，数据库和上传文件写入指定位置；
- 原 Uvicorn 启动命令仍可使用；
- `/api/health` 正常反映数据库和模型配置状态且不泄露敏感信息；
- `docs/api.md` 能清晰区分现有接口与计划接口；
- 基础自动化测试全部通过且不污染 `data/`；
- README 的配置、启动和测试步骤与代码一致；
- 未配置真实凭据时，交接明确标记真实模型验收仍待团队完成。
